# 数据可得性矩阵与功能裁剪决定

本文件是本技能所有功能取舍的**证据基础**。任何功能的启用或删除都必须能追溯到这里的探测结果。

复现方式：

```powershell
python skills/a-share-rotation-trader/scripts/probe_data_sources.py --date 20260814
python skills/a-share-rotation-trader/scripts/probe_limit_pool_history.py
python skills/a-share-rotation-trader/scripts/probe_fzline_depth.py
python skills/a-share-rotation-trader/scripts/probe_limit_reconstruction.py --tail 70
```

探测时间：2026-08-15；最新交易日：2026-08-14。

## 判定原则

一个功能要保留，必须同时满足两条：

1. **实盘可得**：当前能取到计算所需的输入；
2. **可验证**：拥有足够历史，能满足本技能自身要求的走样本外回测。

只满足第 1 条的功能不保留为"降级版本"，直接删除，避免出现永远无法校准却持续参与决策的指标。

## 两个决定性发现

### 腾讯 `qfqday` 是等差复权，不是等比复权

实测 601330.SH：连续多个交易日 `raw − qfq` 恒为 0.32；2025-11-11 跳为 0.22；2026-07-08 归零。即腾讯用"原价减累计分红"实现前复权，而非"原价乘因子"。

后果与处理：

- 只按等比（`qfq/raw` 分段恒定）检验，会把大批正常复权的股票误判为"未复权"（改造前实测 12 只中误判 7 只）；
- 等差序列会**扭曲百分比收益率**，不能直接用于 RPS、跨日收益、回撤；
- `verify_qfq.py` 因此同时检验两种约定，并从台阶反解每次派息与对应**等比因子**，供下游重建等比前复权序列。

### 涨停生态必须本地重建，不能用第三方涨停池

东财涨停池只有约两周历史，炸板池与跌停池接口已失效，无法满足 60 日滚动分位（需 ≥40 个有效观察）与走样本外回测。

改为用本地日线重建，并以东财涨停池作为校验集。校验结果：

| 交易日 | 本地重建 | 东财 | 差异说明 |
|---|---:|---:|---|
| 2026-08-14 | 63 | 63 | 完全一致 |
| 2026-08-13 | 62 | 59 | 多出 3 只全为 ST（`*ST未来`/`ST新元`/`*ST容越`），均为各自真实限制下的足封涨停 |
| 2026-07-31 | 102 | 99 | 同上，差异全部来自 ST |

**连板高度逐股完全一致**（62/62、59/59），漏判 0 只。差异来自东财涨停池排除 ST，而本技能按规范把 ST 保留在广度统计、从接力指标中剔除。

重建过程中修正的一个偏差：涨跌幅限制不能靠名称表推断。本地名称表滞后于撤销 ST 公告，会把已恢复 10% 的股票按 5% 判定而虚增涨停（实测多出 4 只）。改为实测确认——仅当近 60 日最大绝对涨跌幅未超过 6% 才认定处于 5% 限制。

| 两市成交额分位 | 本地日线 | 是 |
| 行业映射与板块聚合 | `tdxhy.cfg` | 是 |
| 次新股名单与上市阶段 | 本地 `.day` 首条 + 腾讯首条日 K 交叉校验 | 是 |
| 当日盘中价格路径与总成交额 | 腾讯当日分钟 | 否，仅实盘观测 |

### 摒弃

| 删除的功能 | 原因 |
|---|---|
| 东财估算资金流（个股与行业） | 全市场接口 502；逐股接口无任何历史，无法回测；原本仅为辅助证据 |
| 同花顺概念定义、成分与资金流交叉验证 | 无版本化历史成分，无法回测；概念实体无法与行业口径对齐 |
| **题材（概念）归属层** | 唯一本地源 `block_gn.dat` 落后一年；同花顺无历史。归类只能由 LLM 每日判断，历史无法重算，`ST_cycle` 因此无法回测 |
| 集中度 `C`（最大题材涨停占比） | 依赖题材归属 |
| 软硬链接相对强度 `SHS` | 依赖题材归属与人工分组 |
| 缩圈抱团 `regime_override=concentration` | 判定条件依赖 `C` |
| 分钟固定目标资金效能 `CER_adv` / `CER_quality` / `TTR` / 保持率 / `CER_rank` | 腾讯分钟只有当日，本地分钟停更两年，无历史可回测；同组分位需 ≥20 样本的历史横截面 |
| `CER_float`（流通市值归一化） | 无经校验的流通市值时间序列 |
| `CER_cash` | 只能同股比较，无横截面价值 |
| 板块资金效能 `CER_sector` / 达标宽度 / `leader_share` | 需要固定成分股的全历史分钟数据 |
| 东财炸板池/跌停池/涨停池作为生产数据源 | 接口失效或历史不足，改为本地重建 |
| 本地分钟数据读取器 | 停更两年，覆盖不足 |

### 降级保留但不参与排序

`CER_D1` 日线量价效率代理（`正收益% / (成交额/ADV20)`）保留，因为它能用本地日线全历史计算和回测。但在完成走样本外验证前，只作观测字段输出，不参与任何排序或仓位决定。

### 腾讯复权对账降级为诊断

用户明确指定使用本地通达信数据后，腾讯 `qfqday` 不再作为正式 G0 的阻塞源。原因是其等差复权约定与本地等比重建不同，且少数序列存在无法稳定换算的异常。正式门改为本地运营一致性检查；腾讯结果只能作为外部异常提示，不能被描述为已经完成的独立证明。

## 覆盖边界

- 仅沪深 A 股。北交所（8xx、920xxx）不在本地 `vipdoc` 中，一并排除。实测 2026-08-14 东财涨停池含 920083.SZ，本地无该标的——**不得把本口径称为"全 A 股"**。
- 涨停生态的接力指标剔除 ST、一字板；广度统计保留全部涨停。两套口径必须分别标注。
- 除权日在未复权序列上会产生假涨跌停，已按"跌幅超过限制 1.5 倍"剔除并计入 `suspect_adjust_n`。

## 尚未解决的校准缺口

`ST_cycle_v1` 的阈值（20/60/85）与权重仍是待验证参数，输出中 `st_cycle_formal=False`。已具备回测条件（本地全历史），但本次未完成走样本外验证。在验证完成前：

- `ST_cycle` 只用于风险上限参考，不得作为唯一仓位依据；
- 不得把阈值或权重写成已验证事实；
- 状态分布实测（近 500 个交易日）：修复 237、冰点 161、主升 86、高潮 12、退潮 4。

改造中修正的分布退化问题：合成分是多个分位数的加权平均，会向中间压缩并整体抬升，直接用阈值 60 会让"主升"占到 49% 的交易日。现对合成分再做一次 250 日滚动分位，使 20/60/85 真正对应分布位置，主升降至 17%。

| AMT | | | | +1.00 | +0.04 | +0.21 |

结论：

- `B` 与 `YLR` 相关 +0.65、与 `FR_inv` 相关 +0.41，信息冗余，**已从合成分中删除**；
- `AMT`（成交额分位）与所有涨停生态因子相关系数在 ±0.15 以内，是唯一近似正交的维度，**已提升为正式入分项**（v0 完全排除了成交额，而"流动性收缩但涨停生态尚可"正是需要识别的结构）；
- 收缩后的 `J2` 与其他因子相关性均不超过 +0.26，独立性好于改造前的预期。
