# A股分析 HTML 报告规范

## 目标

把分析压缩成“先决策、后证据、可追溯”的单文件页面。它必须适合盘中快速扫读，也能在盘后打印或归档；不是把 Markdown 原样套一层网页外壳。

默认版式由 `run_integrated_decision.py` 生成。盘后复盘或盘中叙事可采用[行动卡布局](action-card-output.md)：先两段结论，再口径与拒绝清单，再主线结构 / 次级方向 / 唯一计划 / 六列行动卡。**版式切换不改变门控结论。**

## 文件与技术约束

- 默认路径：`output/a_share_analysis_YYYYMMDD_HHMM.html`。
- 使用 UTF-8、`lang="zh-CN"` 和响应式 viewport。
- HTML、CSS、图表和必要交互全部自包含；优先静态 HTML + 内联 SVG。
- 禁止外链 CSS、JavaScript、字体、图片和 CDN。不得依赖联网才能读懂结论。
- 模板位于 `../assets/report-template.html`；可以替换、删除或复制组件，但不得把未使用卡片留空。
- 最终文件不得包含 `{{PLACEHOLDER}}`、`NaN`、`Infinity`、调试文本或无来源的伪精确小数。
- 表格须有表头；图形须有标题、单位、时间范围和替代文字或文字摘要。

## 信息层级

### 首屏：30 秒决策区

首屏必须同时看到：

1. 报告对象、证券代码、分析时间、数据截至时间、价格复权状态和置信度。
2. 宏观市场状态、量化情绪状态、`ST_cycle`、盘面过程阶段。
3. 账户总仓位上限和当前动作：持有 / 减仓 / 条件买入 / 零交易。
4. 唯一主计划：触发条件、计划区间、首仓/上限、取消条件、硬失效和 T+1 次日动作。
5. 数据新鲜度与降级提示。缺账户数据或分钟数据时必须在首屏显示。

### 第二层：结构与证据

- 市场宽度、涨停/跌停、炸板率、量能同比、指数与均价。
- 第一主线、次主线、防守、伪轮动；龙头—中军—弹性股是否共振。
- 个股或板块 RPS、ATR、均线/前高乖离、价格与成交量图。
- 行业共振表：成分数、5/20 日中位收益、站上 MA20 宽度、`RPS_120` 中位、成交额/`ADV20`、共振分、是否单股驱动。
- 候选池表：**逐股标注主线地位与是否可执行**；次主线标的须明确写"仅观察"。
- 仓位卡须展开三项止损下限（计划距离、涨跌幅限制×0.6、1×ATR20）并标明哪一项起作用。
- 不得出现资金效能卡的分钟级字段（`CER_adv`/`CER_quality`/`TTR`/保持率/同组分位/板块达标宽度）——这些指标已整块删除，见[量价效率](capital-efficiency-ratio.md)。`CER_D1` 只能作为观测列出现，并标注"未完成样本外验证、不参与排序"。

### 第三层：解释与审计

把“事实”“推断”“交易假设”分成三个视觉独立区域。随后列出风险四项、机会成本、数据来源、口径异常和指标版本。每个关键数字应能追溯到来源或计算口径。

## UI 设计规则

- 使用卡片式 12 列栅格；宽屏最大内容宽度建议 1360—1480px，手机转为单列。
- 首屏决策横幅使用高对比深色底；主内容使用浅色底，避免长时间阅读疲劳。
- A股涨为红、跌为绿、中性为灰；同时展示 `+/-`、`↑/↓` 或文字标签，满足色觉可访问性。
- 金额统一显示元 / 万元 / 亿元，百分比统一保留足够而不过度的小数位。
- 数字使用等宽字体回退；正文最小 14px，关键动作与仓位不小于 18px。
- 风险和失效条件用琥珀/红色警示，不与上涨红混为同一种视觉语义；加“风险”文字标签。
- 表格首列可固定，行距适合盘中扫读；不要用大段段落替代表格或短卡片。
- 价格图与成交量图共享时间轴；RPS、CER 等不同量纲指标不要强行放在同一纵轴。
- 超过两屏时提供页内目录；打印时隐藏非必要控件并避免卡片跨页断裂。

## 质量检查

交付前至少检查：

- 首屏是否无需滚动就能找到动作、仓位、触发和失效。
- 红绿是否同时有符号或文字；手机宽度是否没有横向溢出。
- 来源时间是否早于或等于报告时间；单位、复权和分钟累计额是否一致。
- 价格来源是否明确显示“同花顺 `v_daily_qfq` 前复权 / 未取得”；本地运营 G0 未验证时价格类跨日指标是否停算；不得把通达信 `.day` 原始价标成前复权；本地门须披露其不是独立外部证明。
- 缺失值是否明确写为“未取得/不适用”，而不是 0。
- 是否残留已删除功能的字段（估算资金流、题材/概念归属、分钟级 CER、`CER_float`）。
- 是否把行业维度写成了“题材主线”——本技能没有题材维度。
- `ST_cycle` 是否标注了 `st_cycle_formal` 状态；为 false 时是否写明"仅作风险上限参考"。
- 覆盖边界是否写明"沪深 A 股，不含北交所"，而非笼统称"全 A 股"。
- 唯一计划是否真的是一个计划；备选不得与主计划同时触发。
- 关键风险、T+1 约束和不操作机会成本是否存在。
