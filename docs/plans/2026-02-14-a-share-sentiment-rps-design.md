# A股情绪判断与RPS协同系统设计文档

## 1. 目标与边界

- 目标：在现有 `market_gambler_watch.py`、`rps_system.py`、`feishu_bot.py` 基础上，统一情绪判断口径，先实现稳定情绪信号，再支持云上定时与手动调用。
- 边界：本阶段不做全自动下单，只做半自动决策支持（信号、仓位建议、候选池与推送）。
- 原则：参考现有实现，减少重构；硬风控优先；口径固定；结果可回测可复盘。

## 2. 总体架构

系统分为四层：

1. 数据采集层（`market_gambler_watch.py`）
2. 情绪评分层（`feishu_bot.py`）
3. 风控与选股层（`rps_system.py` + RPS阈值）
4. 输出与协同层（飞书卡片 + 多维表格 + 回测报告）

核心决策顺序：

1) 先过大盘硬风控（沪深300 vs MA20）  
2) 再计算情绪分（0-100）  
3) 再执行广度修正（冰点封顶仓位）  
4) 最后决定是否启用 RPS 选股结果

## 3. 统一情绪判定口径

### 3.1 指标定义（盘后日线）

- 涨跌比：全市场上涨家数 / 下跌家数
- 涨停跌停比：涨停数 / 跌停数
- 炸板率：炸板数 / (涨停数 + 炸板数)
- 赚钱效应：昨日涨停股今日平均涨跌幅
- ETF量比：`510300` 今日成交量 / 近5日均量
- 广度：收盘高于 MA20 的股票占比（完整模式）

### 3.2 评分权重（沿用现有实现）

- 涨跌比：25%
- 赚钱效应：25%
- 涨停跌停比：20%
- 炸板率（逆向）：15%
- ETF量比：15%

输出：情绪分 `S`（0~100）。

### 3.3 仓位映射

- `S >= 80`：80%
- `60 <= S < 80`：60%
- `40 <= S < 60`：30%
- `20 <= S < 40`：10%
- `S < 20`：0%

### 3.4 硬约束（优先级高于情绪分）

- 若沪深300收盘 `< MA20`：仓位强制为 0%
- 若广度 `< FREEZE_THRESHOLD(10%)`：仓位封顶 10%

最终可用仓位：

`final_position = min(position_by_score, cap_by_trend, cap_by_breadth)`

## 4. 与RPS选股的协同规则

- 情绪系统负责“该不该做、做多大仓位”；
- RPS系统负责“做什么标的”；
- 当 `final_position == 0` 时，RPS结果仅观察不执行；
- 当 `final_position > 0` 时，RPS候选按分数和流动性排序执行，严格遵守仓位上限。

## 5. 回测设计（日线）

### 5.1 回测对象

- 主回测：仅回测“情绪择时层”对指数的作用（沪深300或510300）。
- 扩展回测：情绪过滤 + RPS候选池表现（后续阶段）。

### 5.2 执行规则

- `t` 日收盘计算 `S(t)` 和 `final_position(t)`；
- `t+1` 日按 `final_position(t)` 对基准进行持仓；
- 手续费、滑点参数固定并可配置。

### 5.3 评估指标

- 年化收益、最大回撤、夏普、卡玛比
- 胜率、盈亏比、回撤恢复时间
- 对照组：买入并持有基准指数

### 5.4 成功标准

- 最大回撤显著低于基准；
- 在回撤改善前提下保持可接受收益；
- 信号稳定，无明显未来函数与数据穿越。

## 6. 云上部署目标（方案B）

### 6.1 运行形态

- 定时触发：交易日 15:35 自动运行
- 手动触发：HTTP入口即时运行
- 输出结果：飞书卡片 + 多维表格 + 本地日志归档

### 6.2 技术建议

- 先用 ECS + 定时任务 + Python 运行环境快速落地；
- 稳定后可迁移为函数计算以降低运维负担；
- 回测任务与日常信号任务使用同一代码仓，不同入口脚本。

## 7. 风险与约束

- 无法保证收益，目标是提高风险收益比与执行纪律；
- A股T+1与隔夜跳空导致止损有缺口风险；
- 题材极端轮动期会出现“高频打脸”，需靠仓位约束控制损失。

## 8. 分阶段里程碑

### 里程碑M1（本地）

- 跑通统一情绪点输出
- 落地最终仓位计算
- 飞书卡片显示“当前情绪点/仓位建议/硬风控状态”

### 里程碑M2（回测）

- 完成日线情绪择时回测
- 输出绩效报告与参数敏感性结果

### 里程碑M3（云）

- 上云定时任务与手动触发
- 飞书自动推送稳定运行
- 形成每日可执行操作清单
