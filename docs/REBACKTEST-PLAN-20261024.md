# 策略卡重新回测与下一阶段路线

版本：2026-10-24，待执行协议。本文不包含本轮收益结果，不代表任何策略已获实盘批准。

## 先把下一步收敛下来

研究问题限定为：**本地通达信 RPS 强势股筛选，在统一可成交约束下，能否带来稳定的净收益改善；回踩入场和宽度过滤各自是否贡献增量？**

接下来一个研究周期只维护这条主线。ETF轮动、超短涨停、杯柄和深度参数寻优先归档等待，不同时推进。已有模块可以继续生成观察池，但观察池不自动变成买入指令。

每天的工作只保留三个结果：数据是否正常、研究组合有哪些信号、今天的宽度图片。每周只做一次协议内复盘；没有通过验收时，允许结论是“暂时没有证据”，无需立即新增策略。

## 所有卡片如何处置

1. 优先适配：本地TDX RPS、趋势回踩；复用 `trend_start` 执行框架，但先验证其限制。
2. 环境附加层：市场宽度、择时、情绪、风控；分别消融，不当成独立选股收益。
3. 后续独立研究：龙回头、口袋支点、ETF轮动及S0–S5。旧成绩保留为历史，不与新口径混排。
4. 暂缓：杯柄前视修复、涨停类ST/板块规则修复、面板26项引擎适配和运行验证。
5. 参数优化器仅记实验次数，不计作额外获胜策略。

每卡最终需要：准确规则/参数版本、全依赖代码哈希、适用股票范围、信号可知时点、数据快照ID、执行模型、成本、试验次数、结果路径和验收结论。状态依次为 `pending_rule_review → data_ready → causal_pass → backtested → forward_observation`；任一步可退回，不使用“代码存在=有效”的跳级。

## 第一轮固定实验

以下为研究默认值，需在运行前登记确认，并非个人资金配置建议。统一虚拟本金100万元、最多10只、单股目标10%；不融资，现金收益按0，现金不足不超买。所有组合共用交易日历、可交易池、流动性和费用口径。

- C0对照：同一合格股票池，按上月末可知信息等权、月度换仓；另列现金和可获得的宽基总收益基准。若只有价格指数，明确标成价格基准，不伪称全收益指数。
- A：本地RPS主筛选L1，冻结当前默认配置，不混入L2/火车轨/早启/极强榜。按RPS120+RPS250降序、代码升序消除并列歧义；每日收盘评估，空位次日开盘按序补入。
- B：A的候选池增加 `pocket_pivot_finder_v2.py` 中强趋势缩量回踩条件。先锁定具体函数和全部参数，再接入；不把口袋支点另一函数也混入。如果适配无法通过因果测试，本轮只跑A。
- C：B叠加一个宽度仓位规则。提议固定为：当日站上MA20占比<20%时，次日总仓位上限50%，否则100%；采用与研究池一致的沪深口径和复权序列。该阈值是待验证假设，不是已证实参数，不根据结果反复调。

A/B统一退出：收盘跌破MA20，下一可成交交易日开盘退出；持有满20个市场交易日也在下一可成交开盘退出。卖出优先，同一天卖出后不重新买回同一只；不进行日内择时。C降低仓位时等比例减仓，按100股取整，记录无法成交导致的超限；恢复上限时只补当日新合格信号，不强行加回旧仓。所有组合固定每股成交金额不超过前20个有效交易日平均成交额的1%，超过则部分成交/记未成交。

这是统一比较协议，不是复制各旧脚本自带止盈止损。若要复现旧成绩，另开“原规则复现”实验，不能与本轮结果混称。

## G0：冻结数据和规则

- 原始来源 `C:/new_tdx`，先读取实际最新交易日、历史起止、股票覆盖和缺失情况，不把系统日期当行情日期。
- 生成只读输入清单：每个文件的大小、mtime、SHA256；冻结除权文件/因子、交易日历、股票池、时点ST/上市/退市状态、行业映射和代码依赖。大文件不放Git，Git保存清单和快照位置。
- 当前工作区有未提交修改，Git HEAD不能代表实际策略版本。记录已跟踪diff，以及用到的未跟踪源文件及其哈希；禁止将个人配置、密钥、持仓一并归档。
- 信号使用当时可知的复权因子生成连续序列；成交、涨跌停判断使用原始价格及当日实际限制。不得直接用前复权价格跳变去判断涨跌停。历史复权锚和停牌对齐做抽样核验，失败即停止。
- 每日横截面只使用当时合格股票计算RPS，不能先用“今天仍存在且历史足够”的全集倒筛历史。若本地缺退市股或历史ST信息，显式标记存活偏差；结果只能作受限探索，不批准实盘。
- 第一轮沪深普通A股；北交所、ETF另开实验。不掌握历史上市/ST状态时，不以当前名单代替历史状态后宣称完整无偏回测。

## G1：无前视与可成交验收

- 全历史批量计算在t日的信号必须等于仅输入≤t数据的结果；抽样覆盖正常日、除权、停牌、周线未收盘、上市边界和极端行情。周线信号只能用已完成周。
- 收盘信号最早下一交易日成交；执行A股T+1，停牌不成交，一字涨停不买，一字跌停不能卖时顺延。涨跌停限制按历史板块、ST和上市阶段定义。缺规则不能静默使用统一10%。
- 成交记录包含信号时间、委托时间、实际成交时间/价格/数量、拒单或部分成交原因、费用和持仓余额。
- 先对20笔交易手工核验，再跑整段。重点审查 `trend_start/engine.py`：已有next-open/T+1/部分限制逻辑，但ST/北交所和上市规则、真实价格限制及资金组合约束仍需检查；不能只凭单元测试通过认定引擎完备。

## G2：历史比较协议

- 先由数据审计给出可用起止；预热至少250个有效交易日后，按时间顺序约60%开发、20%验证、20%封存检验，生成明确日期边界再运行。边界处清仓、交易不得跨段，特征可用之前数据预热。
- 对已经看过、选参过的历史区间全部标记“已污染”；即使重新分段，也不称全新样本外。任何可用历史过短的情况在报告中保留，不为凑年数拼接不一致数据。
- 基础研究费用假设：佣金单边3bp、最低5元，滑点单边10bp；卖方税费和过户费必须由日期化费用表提供，运行前核验来源。未核验时标记成本不完备，只做敏感性研究。另做滑点20bp和40bp压力测试，不挑最好的一档汇报。
- 第一轮只比较A/B/C及对照，不做网格调参。若需改阈值或退出规则，建立新协议版本，原结果保留，登记累计尝试次数。
- 报告净收益、年化/最大回撤/回撤持续期、相对基准净超额、换手/费用、仓位、交易数、拒单率、未平仓估值，以及年度/市场阶段/行业贡献。事件平均收益单独报告，不冒充组合收益。
- 交易重叠时不把每笔当独立样本；不确定性按时间块评估并记录方法。宽度置换检验需要保留序列结构，不用简单乱序得到夸大显著性。

## 决策门槛（本轮预先约定的研究标准）

- 硬门：无前视、数据和会计核验通过；未通过就不排收益名次。
- 证据量：封存检验至少12个月且合计至少100笔已完成交易，不足标为“证据不足”；达到也不自动证明有效。
- 保留候选：基础成本和双倍滑点下均有正净超额，最大回撤绝对值不大于对照；逐年度和集中度检查后，不依赖单个年度或极少数股票才有盈利。达不到则归档失败/不确定结论，不通过换参数抹去失败。
- B相对A，C相对B都必须解释增量。C即使降回撤，也需展示空仓机会成本与收益损失，不能因仓位低就宣称选股能力更强。
- 历史通过后再做至少8–12周不改规则的前向模拟；这是执行观察期，不是统计充分性证明。前向起点必须晚于实际锁定协议/数据日，不能回填已经看过的数据。

## 工程交付和日常节奏

第一阶段：更新源码审阅记录，确认本地RPS实际规则，出数据质量清单。

第二阶段：统一信号接口和执行器，完成前缀测试、20笔交易审计、C0/A最小回测；先回答RPS有没有增量。

第三阶段：A通过后才加入B，再加入C；达不到证据门槛则明确停止扩展，保留结论和排查原因。

第四阶段：锁定胜出或不确定结论，进入前向观察。日期依赖数据质量和适配工作，不承诺固定几天完成。

运行存储建议：`outputs/backtests/<protocol_id>/<run_id>/`，保存 `manifest.json`、规则参数、数据清单引用、交易流水、每日净值、诊断和报告。它们是后续执行应生成的产物，本轮没有生成收益文件。协议和最终小体积结论进Git，行情/数据库/大流水留数据盘并独立备份。

日常内容流程继续使用 `python tools/workspace.py breadth`：本地数据→宽度评估→小红书图片/文案。图片标行情日期、覆盖范围和口径；不把未验证的研究信号写成投资结论，不自动发布。

用户现在只需优先推进一个动作：**把本地RPS主筛选A接入统一、可审计的最小回测**。无需先决定哪套策略“最赚钱”。
