# 右侧观察 V2：趋势、整理、确认分层

研究日期：2026-09-27。行情验证日期：2026-09-23、2026-09-24。
这是规则实验版本，不是盈利能力验证，也不生成交易指令。不改写证据数据库。

## 为什么值得改

V1 把强趋势、短线站线次数、固定平台宽度、缩量、当日放量、收盘位置叠加。
“值得持续观察”和“今天出现特定突破形态”不是同一个集合。V1 当日确认空集
并不等于没有强势股票；把所有条件简单调松也无法证明选股质量提升。

原始公式还有注释与数值不一致的问题：实际 RPS 合计阈值为180，不是185；
MA200/250的30日站线次数是20，不是25；MA5的10日站线次数是6，不是1。
定义的5/60堆量1.8倍条件未接入最终输出。V1已单独保留原公式与 COUNT(X,0)修正版。

## 三层口径

| 层级 | 定义 | 不代表什么 |
|---|---|---|
| 趋势观察池 | 强度、长短趋势、流动性、换手率、高位位置与偏离检查通过 | 不代表当天有突破 |
| 整理观察池 | 趋势池内，前期量能与真实波幅收缩、窄幅、当前接近前20日高点但未突破 | 不代表整理一定向上 |
| 当日突破确认 | 趋势池内，前期整理结构通过，今天收盘超过前20日高点且量能/收盘位置通过 | 不代表未来收益确定 |

整理与当日突破均为趋势池子集；二者因当前收盘是否超过高点而互斥。
报告只列观察池成员，每只仅给最高适用状态；原始审核明细仍留在 all_evaluated.csv。
V1继续单独可运行，V2不覆盖它。V1回踩分支依赖移动均线而没有固定原突破点，
V2暂不沿用，未来需用冻结的历史突破点另行验证，不能把它算作已改进完成。

### 趋势池

- RPS120+RPS250 >180，RPS120≥90，RPS250≥85；来源为外部数据6/7，均除10。
- 收盘>MA20>MA60，MA20和MA60高于5个交易日前。
- 最近30日，站上MA200与MA250分别至少20日。
- 最近10日至少7日成交额>1亿元，当前换手率<10%，缺换手数据不入池。
- 收盘/最近120日最高收盘≥0.9。
- 距MA20≤12%，且价格距离≤3×此前20日平均真实波幅；两个上限同时成立。

没有继续把原来的MA5/MA10短期站线次数与动态回撤COUNT当作趋势池硬门槛。
这属于明确的规则变更，而不是声称与原公式等价；原版结果列依然保留供对比。

### 整理与突破

真实波幅TR=max(H-L, abs(H-前收), abs(L-前收))。ATR0取截至昨日的20日TR简单均值，
不是Wilder平滑ATR；当天大波动不能抬高自身允许偏离。

在日期t：近期窗口为[t-5,t-1]；波动基准为[t-15,t-6]；量能基准为[t-25,t-6]。
近期与各自基准不重叠，避免用“短窗口必然小于包含它的长窗口”冒充收缩。

- 近期平均TR/波动基准≤0.8。
- 近期平均成交量/量能基准≤0.9。
- 近期最高价减最低价≤3×ATR0。
- 昨日收盘位于此前20日高点的95%至100%。
- 整理层额外要求当前收盘也在该95%至100%区间。
- 突破层额外要求当前收盘超过该高点，当日量/此前20日均量在[1.3,3]，
  (收盘-最低)/(最高-最低)≥0.65；无振幅K线不判确认。

这些是待验证的初始参数，并未依据9月24日的入选数量拟合；后续调整应升级版本。

## 通达信如何使用

1. 将 `config/right_confirmation_v2.tdx.txt` 内容粘贴到新建的**条件选股公式**，建议名 `右侧V2`。
2. `MODE:=1;` 是日常趋势观察池；需要整理池时改为2，需要当日确认时改为3。
   也可复制为三个不同名称的公式，仅改变MODE。默认不是“只选当天突破”。
3. 选择沪深A股，另行排除ST、退市整理等风险股；公式名过滤只是辅助，不替代选股范围设置。
   使用日线、完整历史日线与一致的前复权设置，收盘后运行。至少280根有效日线。
4. 核对外部数据6确为RPS120×10、7确为RPS250×10，更新到拟筛选日；
   公式无法证明外部数据的更新日期，不能用旧RPS冒充当日值。
5. 若仍是空集，把 `config/right_confirmation_v2_diagnostic.tdx.txt` 新建为**技术指标公式/副图**，
   不要作为条件选股公式粘贴（它有多个输出）。对一只样本检查各项1/0。
   “数据=0”优先检查日线长度、外部RPS和CAPITAL；“强度=0”查RPS数值与通道映射；
   “观察池=1、确认=0”通常只是当天事件未成立，不是故障。

交付文件与Python默认参数通过自动测试保持一致，但**尚未在本机通达信公式编辑器编译验收**。
公式理论语义对齐不等于终端逐股对账；终端版本、复权、股本和风险股范围可能造成差异。
本地.day成交量解析成股，换手率=成交股数/流通股数×100；终端VOL/CAPITAL使用其自有统一口径。

## 本地运行

在本目录执行（Python3.12，pandas、numpy、pydantic、pytdx）：

```powershell
py -3.12 run_right_confirmation.py --tdx-root C:/new_tdx --date 2026-09-24 --version v2
py -3.12 run_right_confirmation.py --tdx-root C:/new_tdx --date 2026-09-23 --version v2
```

输出在 `output/right_confirmation_v2_YYYYMMDD/report.html`。
`audit.json` 保存参数、原始来源哈希、排除原因和门槛独立通过数；独立通过数不是递减漏斗，不能相加。
`all_evaluated.csv` 含 v2_failed/v2_missing、V1同输入结果以及逐股.day文件哈希。
`setup.csv` 与 `confirmed.csv` 是审核用只读子集，主页面仍只输出值得观察的标的。
