# W1：尾盘试错条件观察指标

版本：tail_watch_w1。建立条件识别、失效记录、收盘复核的研究闭环；不输出委托、仓位或买卖结论。
“齐备待复核”表示这组实验条件成立，不表示已经证明可盈利或适合交易。

## 1. 什么情况下进入人工试错复核

第一版只做尾盘，不把未验证的同一套阈值直接推广到早盘。
在14:45、14:50、14:55三根**已完成**的5分钟K线上评估，以下条件必须同时满足：

| 检查项 | W1初始规则 |
|---|---|
| 前置池 | 该股票属于前一交易日V2观察池；不是用当天收盘筛出的名单回看当天盘中 |
| 站稳平台 | 最近两根完整5分钟K线收盘均高于冻结平台P |
| 均价确认 | 两根收盘分别不低于各自当时的全日累计成交均价VWAP |
| 量能确认 | 最近两根平均量 / 此前六根平均量 ∈[1.3,3]，两个窗口不重叠 |
| 收盘位置 | (当前价−截至此刻日低)/(截至此刻日高−截至此刻日低)≥0.65 |
| 前期窄幅 | 此前六根的最高价−最低价≤1.5×冻结ATR |
| 不过度偏离 | 0<当前价−P≤0.5×ATR；0<当前价−MA20≤3×ATR；距MA20≤12% |
| 数据核验 | 完整开盘以来5分钟数据、正确股/手单位、相邻交易日、同一证券、价格口径一致 |

P为截至前一交易日的20日最高价，**包含前一交易日**。
ATR为截至前一交易日的20日真实波幅简单均值；不是Wilder平滑版本。
MA20也冻结在前一交易日。与旧报告“前20日高点”不同：旧字段排除报告当天，
直接复制它用于下一交易日会少包含一天，因此准备脚本从原始日线重新计算。

这里的1.3、0.5ATR、1.5ATR等都是待检验的研究参数，没有胜率或收益保证。
同日早些时候已经站上平台的股票也可能满足尾盘条件；W1不声称识别“首次突破”。

## 2. 失效与收盘复核

- 状态0：等待窗口或条件未齐备。
- 状态1：条件齐备，等待人工复核。首次出现时间被保留，不把每次出现重复算新样本。
- 状态2：此前曾齐备，现在部分条件不再成立，仍需复核。
- 状态3：首次齐备后，某根已完成5分钟收盘低于 `P−0.5×ATR`，记为结构失效。
  当天状态保持失效，即使后续反弹也不重新置为齐备。
- 数据不足：单独的“数据待核验”，Python输出 `ready=null`，不是条件不成立。
- 14:57之后Python不再输出齐备资格；15:00记录收盘是否仍高于P、VWAP及是否已失效。

`P−0.5×ATR`是检验形态假设的固定参考，不是止损委托价，也不能保证实际损失不超过该幅度。
尾盘仍存在隔夜跳空、公告、流动性和成交限制；指标不解决执行问题，也没有连接券商。

窗口止于14:55，避开14:57开始的收盘集合竞价。[上交所投资者教育](https://edu.sse.com.cn/best/article/gsxlsc/c/4725367.shtml)
说明连续竞价与集合竞价的区分，14:57—15:00不接受撤单；W1不模拟竞价成交。

## 3. 通达信副图使用

### 安装显示版1.1（源码粘贴，不是导入txt）

1. 先打开对应股票的已生成源码。例如历史复核瑞凌股份：
   `output/tail_watch_w1_20260924/300154.SZ.tdx.txt`，此文件只绑定300154及2026-09-24。
   它不是今日可直接使用的通用指标。`config/tail_watch_w1.tdx.txt`是默认关闭的空模板，
   直接粘贴空模板只会显示“未启用”，不能为看到信号而强行改启用位。
2. 通达信按Ctrl+F进入公式管理器，在“技术指标公式”下选择分类（如其他类型）→“新建”。
3. 名称可填 `W1RL0924`，画线方法选“副图”；复制上述txt的完整源码到编辑区。
   txt是源码文件，不是tn6等导入包，因此不要用“导入公式”直接导入这个txt。
4. 点击“测试公式”，无错误后保存。有编译错误时保留错误文字和行号，不要删除保护条件来通过测试。
5. 打开300154，切到5分钟、不复权，加载完整前一交易日及绑定日分钟线；
   在副图区域右键→选择副图指标→选 `W1RL0924`。也可通过键盘输入公式名称调用。

这些界面操作依据通达信官方[公式管理器](https://help.tdx.com.cn/gspt/docs/markdown/tdxgs-1d1k7b2r1ihug/tdxgs-gsbj/tdxgs-xjgssm.html)
及[技术指标调用说明](https://help.tdx.com.cn/gspt/docs/markdown/tdxgs-gsxt/tdxgs-1d1knga9g35l0.html)，
具体版本菜单文字可能不同。原生编译和实际渲染仍需终端验收。

### 明显标记怎么读

| 显示 | 含义 |
|---|---|
| 黄色粗柱＋“★ 首次齐备” | 当天第一次出现全部W1条件，供人工复核；不是下单指令 |
| 后续普通黄柱 | 此次评估仍齐备，不算新的首次样本 |
| 青色短柱 | 之前齐备，现在部分条件不再成立 |
| 灰色粗柱＋“X 结构失效” | 第一次确认结构失效；后续灰色短柱保持当天失效状态 |
| 顶部文字提示 | 明示未启用、股票/日期/周期不匹配，或分钟数据不足 |
| 底部六项“是/否” | 分别对应站稳、均价、量能、位置、窄幅、偏离；仅在数据有效时显示 |

星号/X下面的数字是实际评估时刻，例如1445表示14:45。
由于只读已完成K线，星号画在随后那根K线的位置：例如14:50的图形位置显示14:45结果。
顶部固定文字对应最新数据栏，六项诊断也对应其上一根，**不是**鼠标所指任意历史K线；
查历史某根可结合上方指标数值栏和标记下的评估时间。
日后若文件已有其他日期的分钟线，顶部显示“日期不匹配”是预期保护，历史绑定日的标记仍需看该日。
绿色“是”仅表示单项检查通过，六项全是也仍须满足名单、时间、数据和状态保护。

显示部分采用官方[DRAWTEXT_FIX等绘图函数](https://help.tdx.com.cn/gspt/docs/markdown/tdxgs-1d1k7biu16p6s/tdxgs-1d1p8n2edn4io.html)。
建议保留足够高、宽的副图区域；当前样式按深色背景设计。显示版没有修改筛选阈值。

`config/tail_watch_w1.tdx.txt` 为**技术指标/副图模板**，不是条件选股公式。
模板默认 `ENABLED:=0`，价格和日期为0，故没有配置时不会生成有效状态。
建议使用准备脚本生成的逐股版本，不要将一只股票的P/ATR/MA20套给所有股票。

1. 先在前一交易日收盘后生成V2观察池，再为明确的下一交易日准备计划。
2. 将输出目录对应证券的 `.tdx.txt` 粘贴到通达信新建的技术指标公式。
3. 打开**绑定的那只股票、绑定日期的5分钟图**，使用与计划一致的不复权分钟价格；
   日线参考值已通过本地前复权重建对齐至前日实际价格，目标日有股本/除权事件时默认禁用。
4. 加载完整前一交易日及当日5分钟数据。代码、日期、周期或计划核验失败时状态为−1。
5. 读取“上根时刻”和“状态”。公式所有公开状态取 `REF(...,1)`，
   因此图上正在形成14:50那根K线时，显示的是14:45已完成K线的结果，不读取未完成K线。
   14:55结果在下一根（标为15:00的）K线开始形成后可见。不要把绘制位置当成评估时刻。
6. 原生副图保留最后已完成K线的历史状态，不能充当当前时钟授权；
   即使14:57以后屏幕仍显示历史状态1，也不代表评估窗口仍然开放。
   Python回放显式校验 `as_of` 并关闭窗口，收盘复核也以Python输出为准。

公式不使用 `DYNAINFO`、`FROMOPEN` 或 `#DAY`，避免用当前实时量比或当天完整日线冒充历史信息。
通达信官方文档说明：VOL单位是手、AMOUNT单位是元；TIME适用于日线以下；
跨周期引用可能取到未来数据。因此原生VWAP使用 `SUM(AMOUNT)/(SUM(VOL)*100)`，
Python则要求成交量已换算成股。[通达信函数表](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)

**尚未在本机通达信编辑器编译验收或完成分钟逐根对账。**
Python对分钟缺根、重复、乱序和成交金额/量单位进行严格校验；原生公式只有基础条数检查，
无法保证发现“缺一根又重复一根”等错误。两者不能被描述为已完成终端等价性证明。

## 4. 本地准备与回放

在策略目录运行：

```powershell
# 历史复核例子：使用9月23日名单，准备9月24日计划，绝不反过来。
py -3.12 prepare_tail_watch.py --report-dir output/right_confirmation_v2_20260923 --session 2026-09-24 --output output/tail_watch_w1_20260924

# 以下为空数据路径测试，不是盘中回测。
py -3.12 run_tail_watch.py --plan output/tail_watch_w1_20260924/300154.SZ.plan.json --bars config/empty_minute_bars.json --as-of 2026-09-24T14:50:00 --output output/tail_watch_w1_20260924/missing_data_check
```

准备脚本用本地上证指数日线确认两个日期相邻且目标日有交易记录，不用“工作日=交易日”猜测。
若目标日尚无指数日线，计划默认未核验并禁用；这是当前离线准备器的限制。
实盘部署需要一个受核验的交易日历和盘前除权校验入口，目前未实现，不应直接把核验位强行改为True。
历史计划只对绑定日期有效，不能在下一个交易日原样复用。

实际回放用真实分钟文件替换 `--bars`，支持UTF-8 CSV或JSON列表，必须包含：

```text
ts_code,end,open,high,low,close,volume_shares,amount_yuan
```

`end` 为上海时间的5分钟结束时刻，格式如 `2026-09-24T14:45:00`（无时区后缀，固定解释为Asia/Shanghai）。
日内顺序：09:35…11:30、13:05…15:00，每5分钟一根。与供应商不同的时间标签须先核对转换。
数据应覆盖开盘到评估时点；停牌、漏数、单位不明等不能猜补。未来时间戳K线不参与当前判断。
`volume_shares`单位股，`amount_yuan`单位元；价格使用当时未复权价格。
开盘集合竞价是否并入首根5分钟K线，要在供应商转换时统一，不能混用不同VWAP口径。

输出 `state.json` 包含首次出现时刻、失效时刻、逐次六项检查、
最后完整K线时刻和计划/分钟文件哈希。`last_window_bar_end` 标示检查项所属的尾盘窗口，
不能把14:55的检查值误称为15:00值；`close_review`单独记录15:00复核。

  这是计划生成数，**不是25只出现W1条件**。

- 离线合成样本检查正向齐备、未完成K线排除、未来不改变已知结果、缺根/重复/乱序、
  单位错误、绑定错误、结构失效保持及偏离过大。合成样本不等于真实绩效回测。

  不等于全工程类型检查通过。全库既有静态检查问题见RIGHT_CONFIRMATION_V2.md。
- 显示版1.1新增首次标记、失效标记、六项提示和绑定错误解释，回归更新为42项通过。
