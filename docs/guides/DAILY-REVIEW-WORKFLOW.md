# 每日复盘流程：手动、定时、小红书素材

一条命令完成每日复盘：数据检查 → 综合看板 → 小红书图片与文案。只生成素材，**不登录、不发布**。

## 一、每天的流程

| 步骤 | 做什么 | 谁来做 |
|---|---|---|
| 1 | 收盘后（15:30 以后）在通达信里下载当天日线 | 你 |
| 2 | 运行复盘总控（见下） | 手动或定时任务 |
| 3 | 看看板 `outputs/daily_board_<日期>.html`，用 `/daily-review-sop` 写五层复盘与明日计划 | 你 + Claude |
| 4 | 打开 `outputs/xhs/<日期>/`，核对图片和 `post.md`，手动发布 | 你 |

```bash
python scripts/daily/run_daily_review.py
```

常用参数：

| 参数 | 作用 |
|---|---|
| （无） | 用通达信最新交易日，适合手动运行 |
| `--require-today` | 必须是今天收盘后的数据；周末直接跳过，未收盘或还没下载日线就等待（定时任务用） |
| `--wait-minutes 90` | 数据没准备好时最多等 90 分钟，每 5 分钟检查一次 |
| `--date 2026-10-23` | 指定日期（重做历史某天） |
| `--force` | 已完成的步骤也重新运行 |
| `--with-forward-log` | 同时记录前瞻账本（**首次运行会冻结规则**，见下） |
| `--open` | 完成后打开素材文件夹 |

退出码：0 完成；1 某一步失败（日志里有原因，重跑会跳过已完成的步骤）；2 数据没准备好（未收盘、日线未下载或休市）。
日志：`outputs/logs/daily_review/<日期>.log`。耗时约 8 分钟（看板约 4 分钟）。

## 二、做成定时任务

```powershell
.\scripts\daily\register_daily_review_task.ps1                  # 工作日 17:30
.\scripts\daily\register_daily_review_task.ps1 -Time 18:00 -WithForwardLog
.\scripts\daily\register_daily_review_task.ps1 -Remove          # 取消
```

- 以当前用户身份运行，不需要管理员权限；电脑需要开机、不休眠。
- 任务从 17:30 起最多等 90 分钟（每 5 分钟看一次通达信日线是否更新）。**通达信的日线需要你先下载**，任务不会替你下载。
- 休市日、没下载日线时会等到超时后退出（退出码 2），不会生成错误日期的内容。
- 手动试跑：`Start-ScheduledTask -TaskName ARPS_DailyReview`。

## 三、小红书素材

每个交易日生成 6 张 1080×1440 图片和一份 `post.md`：

| 图 | 内容 |
|---|---|
| 1 | 底部温度计状态阶梯、三个核心数字、昨日→今日变化、接下来看什么 |
| 2 | 涨跌家数与成交额占比、近 60 日宽度曲线 |
| 3 | 短线主线：概念指数近 5 日最强、涨停原因热词、连板梯队（同花顺） |
| 4 | 站上各均线的股票占比、60/20/250 日新高新低 |
| 5 | 底部四层逐层判断 |
| 6 | 波动温度计与八项分项 |

`post.md` 含标题（≤20 字）、正文（≤900 字）、话题标签，所有数字由数据生成。

**设计取舍（有意为之）**
- 只讲市场整体和主线题材，**不点名个股**，不写买卖建议，文末带风险提示，降低合规风险。
- 主线题材一页只回答“资金在炒什么”，并注明追涨停、追突破在历史回测里是负收益。
- 不自动发布：小红书没有面向个人账号的公开发帖接口，用浏览器自动化登录发布容易触发风控且违反平台规则。发布前请自己核对数字和措辞。

## 四、前瞻账本（可选）

`--with-forward-log` 会运行 `run_forward_log.py`，对冰点/修复引擎只记账、不下单。**第一次运行会生成 `freeze.json` 并冻结规则**（含代码文件哈希），之后修改任何冻结文件都会被拒绝。需要先确认代码已定稿再开启。

## 五、已知限制

- 依赖通达信日线（复权用 gbbq）和同花顺接口；同花顺接口失败时对应区块显示“未取得”，其余照常。
- 2023 年以前退市的股票本地没有，抄底类历史统计偏乐观。
- 底部温度计的“推力确认”历史样本只有十几次，文案里已标注“仅供参考”。
